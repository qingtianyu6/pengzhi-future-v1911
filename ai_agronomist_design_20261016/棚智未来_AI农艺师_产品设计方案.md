# 棚智未来「会学习的AI农艺师」产品设计方案

设计版本：V1.0  
日期：2026年10月16日  
交付性质：产品设计与独立交互概念稿；新增能力尚未因本方案实施。预览中的棚况、时间线、曲线、方案和研究内容全部为示意。

## 1. 核心设计

让每座大棚拥有持续积累生产记录的AI农艺师：理解当前状态，提出多个下一步方案，组织观察与生产研究，并把有依据的经验整理为可复用的农事流程。

用户进入平台后能够回答五个问题：

1. 这座大棚目前处于什么状态？
2. 采用不同安排，可能出现什么变化？
3. 还有哪些关键问题值得进一步观察？
4. 已有经验在当前条件下能否复用？
5. 我提出一个生产目标，系统怎样组织后续工作？

五项能力不是五个独立聊天窗口，而是围绕同一大棚、同一批次、同一问题共享数据与处理记录。

对外表达：
“棚智未来让AI理解大棚、比较方案、组织研究，并从持续生产记录中积累适合本棚的管理方法。”

## 2. 与当前项目的衔接

| 当前基础 | 本方案新增能力 | 初步实现方式 |
| --- | --- | --- |
| 三维大棚与环境指标 | 生长档案与状态模型 | 先关联真实批次、区域、环境与人工观察，再逐步增加经过验证的生长模型 |
| 短时处置模拟 | 多方案情景推演 | 保存共同基线，比较不同安排，展示假设、输入与差异 |
| 预警和复查 | AI生产研究助手 | 从反复事件提出研究问题，组织资料、观察设计与结果报告 |
| 知识库与案例记忆 | 农事技能库 | 把案例中的步骤整理成可配置、可版本化的流程草稿 |
| 自然语言任务创建 | 目标编排 | 将目标拆成步骤、依赖、观察节点和已有业务工具调用 |
| AI值守方案 | 主动触发入口 | 值守发现事件后，进入对应的研究、推演或目标计划 |

原有生产总览、监测预警、病害诊断、农事执行、三维大棚、数据管理继续保留。新增一个“AI研究台”统一承载本方案。AI值守中心关注正在发生的事项；AI研究台关注原因、方案、研究与经验积累。

## 3. 目标用户与主要场景

### 3.1 现场种植与管理人员

通过生长档案了解当前批次，通过目标计划安排巡棚、拍照、复测与反馈；遇到异常时查看与自己有关的处理步骤。

### 3.2 农技人员

查看反复问题，建立研究问题、比较方案、检查资料适用性，审阅观察结果与技能版本。

### 3.3 基地负责人

查看多棚目标、资源安排、未解决问题和阶段报告。多棚资源协同放在单棚流程验证后扩展。

### 3.4 贯穿设计的示例

研究问题：“为什么这座番茄棚在清晨反复出现高湿？”

记录关联：同一大棚、同一批次、相关时段、环境记录、灌溉/通风记录、棚外天气、现场观察、既有任务与知识引用。

示例假设：“棚外条件变化”“灌溉时间关联”“通风安排关联”。这些是待检验解释，不是已经得到的原因结论。

## 4. 模块一：生长档案与数字模型

### 4.1 用户看到什么

页面左侧为大棚/种植区域视图，右侧为当前状态和证据。下方时间轴能够回看每一次重要变化。

状态内容：

- 作物、品种、批次、种植日期与人工确认的生育阶段。
- 当前环境、近期异常及数据时间。
- 现场观察：长势、花果、叶片表现、病害复核。
- 已执行农事、人员反馈、待复查任务。
- 哪些字段来自实测，哪些来自人工记录，哪些是模型估计。
- 缺失记录与下一步建议采集的信息。

### 4.2 分层建设

第一层是“有证据的批次档案”：真实数据与时间轴，不依赖新模型即可实现。

第二层是“状态估计”：在足够的照片、标尺、花果计数、栽培记录等输入下研究株高、叶面积、阶段进度等估计；每项输出记录模型、适用范围和验证状态。

第三层是“动态生长模型”：根据具体模型所需的辐射、温度、CO₂、叶面积、管理等输入校准。只有经过本棚数据校准和独立验证的输出才作为预测展示。

第四层才研究采收时间、产量和品质的估计，需要实际花果与采收记录。当前五类环境读数本身不能支撑准确产量预测的宣称。

### 4.3 三维表达

三维视图优先关联区域与对象：点击某一垄，看到批次、观察、任务与问题。

作物外观的颜色、形态和阶段改变，必须对应有来源的状态；示意动画单独标注。未经测量的株高和果实数量不以精确数字显示。

### 4.4 形成的数据资产

每个状态快照包含采样时间、区域、输入记录、来源类型、模型版本/人工确认信息和数据完整性。历史快照不被新解释覆盖，便于后续推演与复盘。

## 5. 模块二：多方案情景推演

### 5.1 操作方式

用户提出问题或选择一个活动事件，系统建立一份固定的基线快照，再形成多个候选方案。

候选至少包含：

- 基线安排：保持当前工作计划，作为比较参照。
- 一个或多个候选调整：具体改变什么，保持什么条件不变。
- 信息补充方案：资料不足时优先增加观察或复测。

用户可以调整观察时段、可用资源与目标偏好。对比结果展示环境趋势、任务安排、资源需求、缺失条件和可能的权衡。

### 5.2 推演层级

A. 流程比较：即使没有新预测模型，也能比较任务步骤、依赖、人员需求、观察覆盖和证据缺口。

B. 环境情景模拟：接入现有短时模拟，记录各方案共同起点、假设、模型版本和结果。

C. 作物生长情景：仅在生长模型和输入足够时开放更长时段。未来3天或7天是可配置研究范围，不是当前已实现的预测时长承诺。

### 5.3 结果表达

每个方案都有：

- 目标与改变的因素。
- 不变的背景条件。
- 使用的数据、知识和模型版本。
- 预计观察什么。
- 输出的性质：流程比较、模型情景或现场实测。
- 哪些条件最影响方案比较。
- 当前无法回答的内容。

“最佳方案”由明确的目标和约束决定，不能仅由大模型给一个无依据的综合分。缺少设备能耗或水量数据时，显示待补充，不能编造成本。

模型推演描述的是给定假设下的可能结果；现场效果需要后续记录和研究验证。推演曲线不自动等于因果证据。

### 5.4 衔接目标计划

选中的方案加入“目标计划草稿”，带上基线、依据和观察节点。正式农事任务仍复用现有业务流程。

## 6. 模块三：AI生产研究助手

### 6.1 发现研究问题

来源包括反复风险、处理后再次出现的问题、方案与实际差异、相似批次不同表现，以及人员主动提问。

研究助手输出：

- 可以研究的问题。
- 已有观察与信息缺口。
- 备选解释及支持/反对证据。
- 为什么值得进一步采集信息。

缺少棚外天气、设备记录或灌溉记录时，直接标记缺失，不通过模型补造背景。

### 6.2 组织研究草案

一份研究草案包含：

1. 研究对象与问题。
2. 需要检验的假设。
3. 主要观察指标、单位和时间窗口。
4. 可比较的棚区、时段或批次。
5. 需要尽量保持一致的背景因素。
6. 需要额外采集的信息。
7. 样本与有效观察的定义。
8. 人员任务、计划与复查节点。
9. 结果分析方法、结论适用范围与停止条件。

选择历史比较、配对观察或现场试验等设计时，由研究需求与实际条件决定。连续传感器采样行数不能直接当作多个独立试验重复。

### 6.3 观察与分析

把计划转成拍照、巡查、补充设备日志和环境复测等任务。归集天气、阶段、管理变化等可能影响结果的因素。

结果报告区分：

- 实际观察到了什么。
- 方案预期是什么。
- 存在哪些偏差和混杂因素。
- 当前结果支持哪些解释，哪些仍不能判断。
- 下一轮需要怎样补充验证。

没有完成观察的研究显示“进行中”；不能因为报告已经生成就变为研究已完成。

### 6.4 研究如何进入经验库

初期沉淀为“案例”或“待验证技能草稿”。是否能推广到其他批次或大棚，必须查看条件匹配和后续验证结果。

反例和无效结果也保存，避免系统只记住看起来成功的案例。

## 7. 模块四：可复用的农事技能库

### 7.1 技能是什么

技能是一份有条件、可执行、能检查结果的生产工作流程。例如：

- 清晨高湿排查与复查。
- 连续阴雨期间的巡棚安排。
- 环境数据中断核查。
- 叶片异常拍摄与人工复核。
- 处理后效果记录。

第一批可由农技人员编写流程模板；AI从案例中提炼的技能先进入草稿。

### 7.2 技能结构

| 内容 | 说明 |
| --- | --- |
| 身份 | 名称、编号、版本、作者/整理者 |
| 目标 | 解决什么问题，完成后应得到什么记录 |
| 适用条件 | 作物、阶段、地区/设施、必需数据与设备 |
| 触发条件 | 用户调用、事件或计划到期 |
| 输入 | 需要哪些当前数据与历史证据 |
| 步骤 | 已登记业务工具、人员任务、依赖 |
| 检查节点 | 何时复查，检查哪些有效新信息 |
| 结束条件 | 流程完成、证据不足、人员停止、转交 |
| 来源 | 知识条目、案例、研究与版本 |
| 适用记录 | 使用次数、实际反馈、失败和反例 |
| 状态 | 草稿、待验证、流程可用、停用 |

“流程可用”表示工作流程可以按已定义条件调用，不代表已经证明提高产量或降低病害。

### 7.3 调用与学习

用户选择技能后先检查输入和条件；缺少条件时列出补充项。使用过程中记录每一步及结果。

经验更新是新增案例、修订适用条件、调整流程与形成新版本。大模型权重不会因为一次任务结束而自动得到有效训练。模型再训练作为独立数据、训练、验证和发布流程管理。

## 8. 模块五：自然语言目标编排

### 8.1 用户表达目标

例如：
“未来一周重点关注这批番茄的开花坐果阶段，安排巡棚、观察和复查。”

系统整理出：

- 目标对象与时间。
- 关注的问题。
- 可用人员、数据和设备。
- 任务步骤与依赖。
- 观察和反馈节点。
- 完成或转交条件。

### 8.2 工作流呈现

以清晰的步骤卡呈现“为什么做、做什么、需要什么、下一步如何判断”。支持查看依据、修改计划、比较版本和保存草稿。

新增步骤只使用平台已有登记工具。尚未具备的动作显示“待接入”或转成人员任务，不把自然语言描述当成已经实现的工具。

### 8.3 动态调整

当数据缺失、任务延误、条件变化或研究出现新结果时，生成计划变更建议，展示旧步骤、新步骤和原因。

旧版本保留，已执行工作不被重写；判断每个变更是否影响原有研究的可比较性。

## 9. 页面结构与视觉设计

### 9.1 新增统一入口

“AI研究台”包含五个视图：

1. 生长档案。
2. 方案推演。
3. 生产研究。
4. 农事技能。
5. 目标编排。

顶部固定当前大棚、批次与内容身份；正式版明确当前内容属于实测、人工观察、模型推演还是示例。

### 9.2 布局

左侧保持简洁导航。主区域承载对象、方案、研究和流程；右侧只放本次上下文、证据缺口和下一步，不重复整页信息。

主视觉采用现有暖白、浅绿、森林绿，研究与推演用淡金或蓝灰作辅助。正文、图表与说明在投屏时保持可读。

### 9.3 棚小智

继续保留当前独立的完整3D形象与原有互动，不因进入研究台自动缩小或替换形象。

在研究流程中可通过气泡提示“还缺少什么记录”“这条结论来自哪些观察”；实际详细内容放进卡片，避免遮挡主操作。

### 9.4 关键交互

- 生长时间轴：切换观察快照与查看来源。
- 方案对比：切换候选、改变观察范围、展开依据。
- 研究助手：从假设生成研究草案，展示缺失条件。
- 技能库：查看步骤、条件、来源、版本和使用记录。
- 目标编排：输入目标、生成示例流程、调整草稿。

本次概念稿中的变化曲线与状态是交互示意，不承担模型输出含义。概念稿内的保存只保留在本次预览内存中，刷新即重置，不创建正式业务任务。

## 10. 统一数据关系

贯穿对象：组织 → 大棚 → 区域 → 种植批次。

围绕这些对象新增以下建议记录：

| 对象 | 作用 |
| --- | --- |
| GrowthObservation | 人员观察、照片、阶段、花果与采收记录 |
| CropStateSnapshot | 某时点的状态及实测/人工/模型来源 |
| ScenarioSet | 一次方案比较的共同基线、目标、输入与候选 |
| ScenarioResult | 各候选的输出、假设、模型、适用范围 |
| ResearchQuestion | 研究问题、观察事实、备选解释和缺口 |
| StudyPlan | 比较设计、观察指标、样本、背景因素和任务 |
| StudyResult | 实际结果、分析、局限、后续验证 |
| AgronomySkill | 技能定义、来源、条件、步骤与版本 |
| SkillApplication | 技能调用与实际反馈 |
| GoalPlan | 长期目标、步骤、依赖、变更与执行关联 |
| EvidenceReference | 统一链接知识、记录、照片、任务、模型和版本 |

复用当前环境、预警、任务、审批、Agent运行、复查、案例和知识检索服务。每个研究、技能和目标都能回到相同来源记录。

## 11. 技术实现路线

### 11.1 状态先于复杂预测

先实现有来源的批次档案和状态快照。根据数据成熟度增加状态估计和生长模型，而不是同时承诺株高、产量、品质等全部预测。

### 11.2 推演服务可插拔

统一方案输入与输出：

- 基线、目标、拟改变的变量、固定条件、观察时段。
- 输入缺失与适用性检查。
- 推演器类型与版本。
- 输出结果、单位、可解释假设与验证状态。

可分别接入流程推演、现有环境模拟、后续生长模型。模型无法支持的输出返回不可用原因。

### 11.3 研究由明确步骤组成

问题提出、资料检索、设计草案、任务生成、观察归集、结果分析、经验整理分成可追溯步骤。复用现有Agent工具和运行记录，不要求先部署五个独立大模型服务。

### 11.4 知识、经验和模型分开更新

公共知识更新遵循来源和内容审核；现场案例保留完整背景；技能更新形成版本；预测模型更新有独立验证集和发布记录。

目标计划调用的是已经登记的能力，未来多棚协同再增加共享人员、设备时间和资源预算的调度模型。

## 12. 实施阶段

| 阶段 | 开发内容 | 阶段交付 |
| --- | --- | --- |
| A：统一档案 | 关联大棚/区域/批次、环境、任务和观察记录；时间轴与证据 | 可回看的真实生长档案 |
| B：方案工作台 | 共同基线、候选比较、缺失条件、现有短时模拟接入 | 一个事件可比较多个方案，并转目标草稿 |
| C：生产研究 | 问题、备选解释、研究计划、观察任务和结果报告 | 一项研究从提出到结果均可追溯 |
| D：技能与目标 | 版本化流程模板、案例来源、技能调用、自然语言目标编排 | 可复用的技能与可调整目标计划 |
| E：模型深化 | 数据采集与校准、状态估计/生长模型、独立验证 | 仅开放达到验证要求的预测能力 |
| F：多棚协同 | 共享资源、工作顺序和不同棚条件匹配 | 基地级目标与资源计划 |

优先选择一座番茄棚、一个批次和一个清晨高湿问题作为贯穿案例。甜瓜建立独立适用条件，后续扩展。

## 13. 验收要求

产品流程：

- 同一案例能在五个视图中关联浏览。
- 每条状态区分观察、估计与提议，能查看时间和来源。
- 每组方案使用同一个基线，改变因素与输入缺失可见。
- 没有模型或数据时不生成精确的生长、产量或成本数字。
- 研究草案清楚列出假设、比较条件、指标与缺口。
- 观察未完成时不输出确定研究结论。
- 研究结果可以反驳原假设，反例能够保存。
- 技能具有条件、步骤、来源和版本。
- 草稿、待验证与流程可用状态在界面一致。
- 目标编排支持修改和比较版本，未接入动作显示清楚。
- 记录不会因为一句AI总结而改变原始事实。
- 正式数据、推演、演示回放与概念稿相互可辨。

模型和效果：

- 时间相关数据按批次/时段合理划分验证，避免把高度相关记录当成独立验证。
- 给出误差、适用范围和不支持的输出，界面同步展示状态。
- 推演性能、建议采纳率、研究完成率、技能复用效果分别记录。
- 生产收益在真实试用或合适比较研究后评估，不根据概念预览宣称增产或节水。

## 14. 答辩讲解方式

用一个问题贯穿五项能力：

1. 生长档案：清晨高湿反复出现，展示对应时段和实际缺失信息。
2. 方案推演：比较基线、调整观察和信息补充方案。
3. 生产研究：AI提出备选解释，生成观察计划。
4. 结果回顾：展示已经完成的观察，说明哪些解释有依据、哪些尚未解决。
5. 农事技能：把适用步骤保存为可追溯技能版本。
6. 目标编排：下一个生产阶段调用流程，形成新的任务与验证安排。

如果现场观察或模型验证尚未完成，就展示对应草案和设计，不把界面示例当成实测结果。

可以突出三个可检验的创新点：

- 同一生产问题贯穿状态、方案、研究和技能的统一证据关系。
- 根据证据缺口主动组织观察与验证，而不仅仅给出一次性回答。
- 基于案例、反例与适用条件更新农事流程，使经验可以复用和修订。

这些是本项目拟实现的产品与技术设计方向，不宣称未经检索验证的全球首创。
