# Promax 棚智 V3.0 · 设施农业生产决策平台

棚智未来是一套面向设施农业生产管理的软件平台，将多源数据接入、环境预测、风险研判、番茄病害辅助识别、生产建议、农事任务和执行反馈连接为完整业务闭环。

## 五个一级工作台

- **智慧驾驶舱**：只负责运行总览，展示当前大棚、生育进程、关键环境指标、风险摘要和任务摘要。
- **数据中心**：统一管理大棚档案、种植批次、CSV/Excel 文件导入和第三方传感器 HTTP 接口。
- **智能研判**：集中完成历史趋势、未来 1～6 小时预测、数据健康度与风险事件分析。
- **病害识别**：番茄叶片六分类、Top-3 候选、置信度门控与人工复核。
- **生产闭环**：可解释建议、处置路径对比、任务执行与 AgriTrace 决策证据链。

AI 不占用一级导航。右下角的 **“棚小智”农业智能体**提供两种对话模式：

1. **通用问答**：不绑定大棚，检索本地农业知识库回答设施农业和平台使用问题；
2. **大棚对话**：绑定一个大棚，按问题读取该棚环境数据、1～6 小时预测、活动预警、农事任务和知识库后再回答。

## 数据接入

系统支持三类环境数据入口：

1. 页面导入 CSV / XLSX / XLSM；
2. 第三方传感器通过 `POST /api/v1/ingest/sensor-data` 直接上报；
3. 已有软件平台继续使用 `/api/sensors/batch` 批量写入标准化数据。

传感器接口按大棚编码接入，可配置 `SENSOR_INGEST_KEY` 并通过 `X-Sensor-Key` 请求头鉴权。系统不绑定具体硬件品牌。

文件导入前会进行字段识别、时间连续性、指标完整度、重复时间点和数值范围检查。没有可用环境记录时，各工作台保持空状态；环境预测满足连续历史数据要求后才会运行。

## 农业知识库

`backend/knowledge_base/knowledge.json` 保存棚小智的本地检索知识。当前覆盖：

- 设施蔬菜冬季/夏季温湿度与通风管理；
- 番茄叶霉病、早疫病、晚疫病、斑枯病、黄化曲叶病毒等风险要点；
- 设施甜瓜分阶段温湿度管理；
- 数据质量、传感器接入和 AI 决策安全边界。

农业条目保留公开来源机构和链接，回答用于生产信息整理与人工决策参考，不替代专业植保诊断。

## 算法能力

### 环境预测

环境预测引擎融合 Seasonal-24、GRU、LSTM、XGBoost 和基于验证结果的组合策略，并按变量和预测时长选择适合的方法。模型中心读取实际模型产物展示当前服务版本和验证指标。

### 病害辅助识别

病害识别模型产物使用 MobileNetV3-Small，对番茄叶片六类状态输出 Top-3 候选结果。模型目前处于评估中，外部测试表现不足以支持自动诊断；所有结果均需人工复核。

## V2.0 高温高湿处置闭环

番茄大棚出现温湿度组合预警后，生产闭环页会展示四种由规则生成的人工候选方案：顶窗检查、风机检查、联合检查和继续观察。每种方案显示操作条件、人工与能耗等级；响应时间和预计风险降幅在获得本棚验证数据前不提供数字。管理人员选择方案并记录原因，系统创建任务草稿和处置记录。任务开始后，可在 30 分钟及 60 分钟记录传感器数据与人工观察。AgriTrace 展示方案选择、执行与复测。处置前后变化仅用于效果跟踪，不作因果结论。

V2.2 业务接口要求登录。每个注册账号创建独立组织空间；管理员可通过 `/api/auth/members` 添加管理员、农技人员、执行人员或观察者。历史库只有一个账号时，原有大棚自动归属该账号；多个旧账号共享的数据会放入“历史数据待认领”组织，避免错误地暴露给任一账号。单组织环境可使用 `X-Sensor-Key` 上报；多组织环境请使用所属组织的管理员或农技人员令牌上报。任务附件通过受控接口读取。

### V2.0.1 稳定闭环

30/60 分钟复测以任务开始时间为基准，在目标时刻前后 10 分钟内选择最接近的一条有效传感器记录；没有合格记录时保留人工观察并标记数据缺失。预警、候选方案、处置、任务状态由后端转换控制；高温高湿预警只有任务完成、60 分钟复测且人工确认风险解除后才能解除。

### V2.1 Case Memory 与 V2.2 相似案例

`GET /api/cases` 和 `GET /api/cases/{id}` 从预警、候选方案、处置、任务、反馈、30/60 分钟复测动态聚合案例，不复制原始业务数据。`GET /api/warnings/{id}/similar-cases?top_k=5` 仅检索当前组织中同作物、同风险类型的完整案例，以温度、湿度、CO₂、土壤湿度和生育阶段的加权距离排序，并展示各方案真实观察次数及中位变化。历史观察不代表方案因果效果，也不自动判定最佳方案。两个能力嵌入现有生产闭环页面，不新增一级导航。

### V2.3 方案证据与 V2.4 What-if

`GET /api/warnings/{id}/decision-support` 为每个候选方案显示现场适用条件、相似案例数、60 分钟实测次数、风险分变化、能耗和人力等级。对不处理、顶窗、风机、联合处置分别模拟 30/60 分钟温湿度与风险区间。历史样本达到要求时采用相似案例观察中位数；否则以近期趋势和明确标记的简化假设生成探索性区间。所有动作仍由人工决定和执行。

### V2.5 本棚模型健康与 V3.0 数据驱动比较

环境预测调用会保存预测快照，后续以目标时刻前后 10 分钟的有效实测计算本棚温度、湿度的 MAE、RMSE、Bias、区间覆盖率和偏差漂移；指标附在每次预测响应中，也可通过 `GET /api/predictions/health?greenhouse_id=...` 获取。预测刚开始运行时没有可验证样本，页面明确显示样本不足。

每个方案至少积累 5 次有实测的 60 分钟案例后，系统给出带样本数的观察性结果估计，并按用户设置的能耗、人力上限计算比较分。该分数不自动选择或执行方案，也不能解释为因果效果。CATE 与 Offline RL 需要更充分且符合条件的数据，当前版本没有启用。

## 本地运行

首次安装：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\setup.ps1
```

开发模式：

```powershell
.\start_all.ps1
```

生产模式：

```powershell
.\start_production.ps1
```

生产模式访问 `http://127.0.0.1:8000`。
生产构建默认使用同源 `/api`；如果前后端分别部署，请在构建前设置 `VITE_API_BASE_URL` 为实际 API 地址。

## Docker 部署

```bash
docker compose up -d --build
```

数据库和上传文件使用 Docker volume 持久化。

## 发布验证

```powershell
.\verify_release.ps1
```

验证脚本会依次执行后端测试、前端 Lint、前端生产构建和模型文件检查。

## 主要目录

- `frontend/`：React + TypeScript + Vite 前端
- `backend/`：FastAPI + SQLAlchemy + SQLite 后端
- `backend/knowledge_base/`：棚小智本地农业知识库
- `backend/app/ml/`：环境预测模型与推理代码
- `backend/app/artifacts/disease/`：病害识别模型产物
- `docs/`：架构、接口和数据库设计

## 2026-10-15 检查后完善

本轮统一了工作区大棚选择、修复游客演示闭环、移动端抽屉与三维面板布局，并补充账户与团队管理。空数据不进入风险或模拟；缺少真实前后快照不能生成效果评估。规则指数与探索性模拟不代表发病概率或已验证疗效。

浏览器回归：先启动本地前端，再在 frontend 目录执行 `npm run test:e2e`（Python 需已安装 Playwright 和 Chromium）。脚本临时启动 8011 端口隔离后端，创建验收账户和数据，不修改日常数据库。完整检查可执行 `powershell -ExecutionPolicy Bypass -File .\verify_release.ps1 -WithBrowser`。

大棚编码在当前部署环境中全局唯一；界面默认生成带组织前缀的编码。同一大棚同一时间多设备的互补指标会合并，已有指标不会被重试覆盖。当前保存方式仍是按大棚时间聚合，不提供完整的逐设备原始流水。

模型新增可移植参数与原生 XGBoost JSON，原产物保留。转换只验证当前运行环境数值一致，不代表完成跨版本训练复现或现场精度验证。以后重新训练后请重新导出可移植文件；源文件发生变化时加载器回退原产物。

登录限流当前为进程内计数。多进程或多实例公开部署需在网关或共享存储补充统一限流。风险规则、处置响应系数仍需现场数据校准；较大三维资源和图片的进一步压缩未纳入本轮完成项。

逐项修复记录与验收证据见 `improvements_20261014/完善与验收记录.md`。


## 棚小智常驻助手（2026-10-15）

官网提供角色和平台使用向导，工作台提供关联当前大棚的真实问答、历史记录、图片辅助识别、任务草稿、审批、语音输入和回答朗读。角色支持拖动、收起、隐藏与恢复，偏好按本机账号保存，三维页面默认使用小入口。

语音由浏览器 Web Speech 能力提供，中文识别可能使用浏览器的在线服务，需要支持的浏览器、HTTPS 或本机地址及麦克风授权。识别后先填入文字，由用户确认发送。关闭助手、页面隐藏时停止录音与朗读。实际麦克风和扬声器效果需在目标设备验证。

交互助手的写入请求携带 `require_confirmation`，服务端在工具执行前保存待确认动作；旧客户端调用契约保留。游客的模型建议同样先显示待确认草稿，不再自动写临时任务。管理员或农艺师确认后可保存，观察员只能查询。未配置外部模型时，正式账号可使用原有本地知识和证据能力，游客会明确提示配置状态。

前端生产构建会包含 `assistant/` 角色素材，FastAPI 同源部署提供相应静态路径。素材、交付说明与验收见 `assistant_release_20261015/`。启动前后端后，在 frontend 目录执行 `npm run test:assistant:browser` 可运行隔离业务检查和浏览器边界检查；需已安装 Python Playwright 及 Chromium。
